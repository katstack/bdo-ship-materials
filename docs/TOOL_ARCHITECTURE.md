# 도구별 기능 경계와 제작 계획

## 최상위 탐색

`App.tsx`는 도구 탐색 셸이다. 함선 성장(`ShipWorkspace`)과 제작 시뮬레이터(`CraftingWorkspace`)를 지연 로딩한다. 실제 기능이 없는 메뉴는 노출하지 않는다.

- 함선 성장: 기존 함대 현황, 선박 단계, 재료, 물교, 수급 계획, 함대·백업.
- 제작 시뮬레이터: 제작노트와 다중 목표 제작 계획. 함선 선택 컨텍스트를 읽지 않는다.
- 기존 함선 URL과 `#/crafting/item/<id>`는 유지한다. 제작 계획은 `#/crafting/plan`으로 직접 접근·새로고침할 수 있다.
- 도구를 바꾸면 각 도구의 마지막 화면으로 돌아간다. 도구별 마지막 주소는 독립 UI 설정 키 `bdo-tools-navigation-v1`에 저장해 새로고침 후에도 복원한다. 함선 화면을 한 번 연 뒤에는 컴포넌트의 저장·Drive 훅을 유지하고 화면만 숨긴다. 따라서 도구 전환으로 예약된 Drive 저장이 취소되지 않는다. 처음부터 제작 도구에 진입하면 함선 도구와 Google 연결을 시작하지 않는다.

## 데이터 경계

| 영역            | 저장·데이터                                      | 책임                                         |
| --------------- | ------------------------------------------------ | -------------------------------------------- |
| 함선 진행       | 기존 `bdo-ship-materials:v1` / 기존 Drive 동기화 | 함대·함선 재고·수급·완료 기록                |
| 제작 계획       | `bdo-crafting-plan-v1` / 독립 JSON 백업          | 제작 목표·제작 전용 재고·경로·수율·표시 설정 |
| 아이템 카탈로그 | 읽기 전용 해시 기반 zstd 청크 / Cache API        | 제작식·획득처·설명·강화 성능                 |

계획 재고를 함선 재고에서 자동으로 읽거나 차감하지 않는다. 제작 계획 초기화·가져오기는 함선 저장 키나 Drive 파일에 접근하지 않는다. 제작 계획은 **현재 Drive 동기화 대상이 아니다**. 향후 동기화할 경우 함선 파일에 암묵적으로 섞지 말고 독립 파일 또는 명시적인 상위 백업 형식을 설계한다.

## 역할별 코드

- `crafting/planTypes.ts`: 계획 타입.
- `crafting/planStorage.ts`, `useCraftingPlan.ts`: 검증·브라우저 저장·오류 처리.
- `crafting/recipeSelection.ts`: 일반 제작식 우선 선택과 부산물 표시.
- `crafting/loadPlanDetails.ts`: 필요한 경로만 로딩. 취소, 중복 제거, 20단계·300개 노드 제한.
- `crafting/planCalculation.ts`: UI/네트워크/LocalStorage에 의존하지 않는 계산 함수.
- `crafting/useCraftingCalculation.ts`: 비동기 경로 로딩과 계산 상태. 재고·정렬 변경은 경로를 다시 다운로드하지 않는다.
- `features/CraftingPlanPage.tsx`, `CraftingPlanTable.tsx`: 계획 편집·백업과 재료 표.
- `features/CraftingNotesPage.tsx`, `CraftingIngredientBranch.tsx`: 검색·상세 탭과 재귀 재료 트리.
- `features/AcquisitionMethods.tsx`, `EnhancementTable.tsx`: 획득처와 성능 표시.

## 계산 규칙

여러 목표를 하나의 의존 그래프로 만든다. 상위 목표의 수요를 먼저 모두 합산한 후 각 아이템의 재고를 **한 번** 빼고, `ceil(부족량 / 1회 예상 생산량)`으로 제작 횟수를 구한다. 따라서 공통 중간 재료가 여러 목표에서 쓰여도 목표마다 반올림하거나 같은 재고를 중복 사용하지 않는다.

- 직접 재료: 목표 제작식의 재료만 펼친다. 다른 목표 자체가 재료라면 그 수요도 합친다.
- 원재료: 제작 가능한 중간 재료를 재귀적으로 펼친다. 사용자가 직접 수급·구매로 바꾼 지점에서는 멈춘다.
- 제작식이 여럿이면 부산물이 아닌 일반 제작식을 우선 선택한다. 다른 제작식은 표에서 선택할 수 있다.
- 추출 제작식에는 결과 생산 수량이 없으므로 기본 **1개 가정**을 경고로 표시한다. 사용자 입력값 역시 기대 수율이며 생산을 보장하지 않는다. 제작식 선택만으로 수율이 확인된 것으로 처리하지 않는다.
- 부산물 제작식은 결과 생산이 보장되지 않음을 추가로 표시한다.
- 강화 장비 입력의 packed ID를 표시할 때만 기본 아이템으로 해석한다. 재고 키는 강화 ID 그대로 사용한다. 미강화 장비를 +10 장비 재고로 대신 쓰지 않는다.
- 순환 경로는 계산을 중단하며 부분 합계를 완전한 필요량처럼 표시하지 않는다. 입력 수량 미확보·최대 깊이·데이터 누락은 경고 또는 오류로 표시한다.

## 추가 리팩토링 후보

이번 변경은 도구 경계와 제작 도메인을 분리한다. 기존 함선 동작을 대규모로 다시 쓰지는 않았다. 남은 `ShipWorkspace.tsx` 내부의 함대 대시보드·선박 단계·수급 계획은 여전히 큰 편이다. 다음 순서로 별도 작업하는 것이 안전하다.

1. 함선 페이지를 역할별 컴포넌트로 추출.
2. 함선 화면 상태·라우팅과 저장·Drive 연결의 훅 분리.
3. 두 도구에서 재사용하는 다운로드·확인 모달·표 정렬 UI 추출.
4. 제작 계획 Drive 동기화 및 실제 생산량 데이터 확보는 별도 기능으로 설계.

사용자 진행 데이터의 불필요한 스키마 변경이나 복잡한 마이그레이션은 추가하지 않는다.
