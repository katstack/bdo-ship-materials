# 생활 숙련도와 재료량 예측

`#/crafting/settings`에서 요리·연금·가공 생활 등급, 레벨, 최종 숙련도, 가공 종류별 숙련도와 예측 기준을 입력한다. 제작 계획 표에서 아이템별 생산량 모형을 **명시적으로 선택**해야 적용된다. 기존 계획의 수동 수율은 그대로 유지한다.

환경설정은 기존 제작 계획 JSON의 선택 필드 `environment`에 저장한다. 이전 파일도 지원하며, 환경설정이 없는 파일을 가져오거나 계획·재고를 초기화하면 현재 환경설정을 보존한다. 함선 저장소와 Drive는 변경하지 않는다.

## 확보한 근거와 확보하지 못한 것

### 숙련도 구간 조회의 두 근거

1. [펄어비스 공식 2025-01-08 업데이트](https://www.kr.playblackdesert.com/ko-KR/News/Detail?groupContentNo=13398): 숙련도별 효과를 구간표로 제공한다. 숙련도→퍼센트 전체 계산식을 공개한 문서로 해석하지 않는다.
2. [bdo-data-extractor의 클라이언트 테이블 형식 문서](https://github.com/iDevelopThings/bdo-data-extractor/blob/main/FORMATS.md#life-skill-mastery-and-level-effect-tables): `cookingstatdata.bss`, `alchemystatdata.bss`, `manufacturingstat.bss`에 숙련도 기준값과 효과 값이 저장되는 구조를 설명한다. 추출기 작성자의 역공학 문서이며 펄어비스 공식 자료가 아니다.

출처·역할·한계·수치의 실제 수집 경로는 `src/data/masterySources.json`에서 관리한다. `masteryLookup.ts`와 환경설정 화면, 수집 스크립트가 이를 참조한다. 두 문서를 출처로 연결했다고 기존 Codex 수치를 클라이언트 직접 추출값으로 바꾸어 표시하지 않는다.

조회는 입력 이하의 가장 높은 구간을 사용하며 보간·수식 역산·외삽을 하지 않는다. 예: 요리 1480→1450→34.11%, 가공 1540→1500→대량 가공 178회분. 표 범위 밖은 양 끝값을 사용한다. 이는 **숙련도 효과 조회**이며 아래의 **제작식별 평균 생산량 계산**과 별개다. 이번 연결은 기존 생산 모형 선택이나 레시피별 기본 생산 규칙을 변경하지 않는다.

- [한국 공식 요리 가이드](https://www.kr.playblackdesert.com/ko-kr/Wiki?wikiNo=102): 숙련도는 최대 수량·상위 요리 확률에 영향을 주며, 대량 요리는 10회분 재료를 소모한다. 대량 요리를 재료 1회분으로 생산량 10배 얻는 것으로 계산하지 않는다.
- [한국 공식 숙련도 확장 안내](https://www.kr.playblackdesert.com/ko-KR/News/Detail?groupContentNo=13398): 요리 확률과 종류별 숙련도에 따른 대량 가공 횟수. 가공 숙련도 자체를 제품 수율 배수로 쓰지 않는다.
- [Codex 요리 숙련도 표](https://bdocodex.com/kr/cookingmastery/), [Codex 연금 숙련도 표](https://bdocodex.com/kr/alchemymastery/): 공개 표의 최대 수량 확률을 0~3000 구간 데이터로 저장한다. 중간값은 아래 구간을 적용한다. 예: 1480 → 1450.

게임의 **레시피별 실제 기본 출력 분포, 등급별 수율 단계, 제작 가능 최소 등급, 기본 상위 결과 확률**은 아직 완전하게 확보하지 못했다. 등급·레벨은 기록과 미설정 판정에 사용하며 이를 근거 없이 수율로 변환하지 않는다. 입력한 최종 숙련도에 등급 효과를 다시 더하지 않는다.

아이템 이름이 ‘특제’라고 해서 상위 확률을 자동으로 결정하지 않는다. 공식 범위가 1~4라 해도 각 결과가 동일 확률이라는 증거는 별개다. 아래 모형은 선택한 범위에 대해 **균등 분포와 별도 최대 프로크 판정**을 가정한다. 화면에서도 사용자 가정임을 표시한다. 부산물 제작식에는 일반 생산 모형을 적용하지 않는다.

## 기대 수율 모형

선택한 기본 범위가 `[a,b]`, 최대 수량 획득 확률이 `p`일 때:

`μ = ((a+b)/2)(1-p) + b·p`

일반 1~4 범위를 사용자가 선택했다면 `μ = 2.5 + 1.5p`가 된다. 실제 적용 범위·분포·요구 등급이 모형과 일치할 때만 유효하다.

- 일반 요리: 요리 최대 수량 확률 사용.
- 상위 요리: **사용자가 검증해서 입력한 기본 획득 확률**에 숙련도 추가 확률을 더한다. 이를 상위 결과 수량의 평균에 곱하며 미획득 출력 0을 포함한다. 기본 확률 미입력 시 모형을 적용하지 않는다.
- 일반 연금: 연금 최대 수량 확률 사용. 연금의 희귀 보너스 아이템 확률을 요리 상위 결과 확률로 대신 쓰지 않는다.
- 가공: 사용자 선택 범위의 균등 평균. 가공 숙련도는 대량 가공 묶음 크기에만 사용한다.
- 수동 평균: 기존 입력값 사용. 분포가 없으므로 95/99 확률 계산을 하지 않는다.

## 95%·99%의 의미

게임 성공률을 실측·보증하는 값이나 평균의 신뢰구간이 아니다. **모형 조건이 맞을 때 목표 개수를 확보하기 위한 보수적인 생산량 하한**을 재료량으로 환산한다.

독립 생산 묶음, 묶음당 최대 `g`회분의 완전 상관, 회당 결과 범위 폭 `w=b-a`를 가정한다. 총 `n`회분 투입의 결과 합에 대한 Hoeffding 하한은 다음과 같이 잡는다.

`생산량 하한 = n·μ - w·sqrt(g·n·log(1/α)/2)`

이 하한이 부족 수량 이상인 최소 정수를 계산한다. 모든 결과의 최솟값이 양수라면 `ceil(부족량/최솟값)`이라는 결정론적 최악값 상한과 비교해 작은 값을 사용한다. 이 역시 선택한 결과 범위가 실제와 일치한다는 조건이 필요하다.

여러 모형 제작 단계가 있을 경우 `α=(1-목표확률)/모형단계수`로 실패 위험을 나눈다. 수동 평균·미확보 분포가 섞인 경우 전체 제작 완료 확률이라고 해석할 수 없으며 해당 항목을 경고한다.

대량 요리 확률이 있는 경우 묶음 상관을 최대 10회분으로 보수적으로 반영한다. 대량 가공 사용을 선택하면 공식 숙련도 구간의 대량 가공 횟수를 묶음 상한으로 사용한다. 개별 결과가 더 독립적이라면 실제 필요한 여유량은 이 모형보다 작을 수 있다. 실패·요구 등급 미충족·서로 의존하는 묶음·조건부 출력 변화는 현재 모형의 보장 범위 밖이다.

수학적 근거: [Hoeffding (1963), Probability Inequalities for Sums of Bounded Random Variables](https://www.tandfonline.com/doi/abs/10.1080/01621459.1963.10500830).

## 데이터 갱신

```sh
pnpm mastery:fetch
pnpm exec prettier --write src/data/masteryTables.json
pnpm test
```

`scripts/fetch-mastery-tables.mjs`는 Codex 공개 숙련도 JSON과 공식 공지 HTML을 조회한다. 열 수·수치 범위·구간 개수를 검증하고 `src/data/masteryTables.json`에 출처·조회 시각을 저장한다. 클라이언트 또는 사이트 형식이 바뀌면 임의 값으로 채우지 않고 실패한다.
