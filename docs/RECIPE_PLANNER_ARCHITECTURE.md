# 레시피 중심 제작노트와 계획

## 책임 경계

1. 원본: `public/crafting/items-*.json.zst`의 추출 필드는 변경하지 않는다. 아이템은 결과물/재료/정보 사전이다.
2. 식별·분류: `recipeIdentity.ts`는 배열 번호나 소스 URN 인덱스 대신 결과물·제작 방법·공방·투입 재료·부산물 원본을 정규화한 내용으로 제작식 ID를 만든다. `catalogAdapter.ts`는 전체 검색 인덱스의 입력 아이템 분류로 제작/장비 회수를 구분한다. 로딩 순서에 따라 회수 경로가 일반 제작으로 바뀌면 안 된다.
3. 레시피 카탈로그: `recipeCatalog.ts`는 재료 칸, 대체재 후보, 선택한 제작식을 해석한다. 보완 규칙은 `src/data/craftingRules.ts`에 출처와 함께 둔다.
4. 사용자 계획: `planTypes.ts`/`planStorage.ts`는 목표 수량, 사용자 수급 방침, 제작식 ID, 제작식별 재료 칸 대체재, 재고만 저장한다. 순환 판정·로딩 상태를 저장된 선택에 덮어쓰지 않는다.
5. 경로 해석: `planRoutes.ts`는 의존 DAG와 진단을 만든다. 순환은 되돌아오는 마지막 의존 간선을 외부 수급 노드로 바꾼다. 사용자의 직접 제작 의도는 유지한다. 장비 회수의 원본 장비는 명시적으로 제작을 선택하지 않은 한 별도 수급이다.
6. 수량 계산: `planCalculation.ts`의 `calculateResolvedPlan`은 해석된 DAG의 수요를 합산하고, 같은 아이템 재고를 한 번만 배분하고, 생산 횟수를 올림 계산한다. 일반 수요와 순환의 외부 수요가 같은 아이템이어도 재고를 두 번 쓰지 않는다.
7. 생산량: `production.ts`는 경로 종류·검증된 출력 범위·등급 조건·환경설정·수동 보정을 결합한다. 숙련도 곡선과 확률 하한 자체는 `yieldPrediction.ts`가 담당한다.
8. 화면: `CraftingPlanTree`는 목표 → 중간 제작품 → 원재료의 관계와 경로별 요구량을 표시하며, 노드 안의 접힌 설정에서 획득 방식·제작식·대체재·생산량을 수정한다. `CraftingSupplySummary`는 직접 준비할 재료를 합산하고 재고 입력·부족량·사용처를 담당한다. 같은 계산 결과를 함께 사용하며 별도로 수량을 재계산하지 않는다. 수급 상태에서도 제작식과 대체재를 변경할 수 있다.

## 제작노트 탐색

첫 화면은 전체 아이템 목록이 아니라 **레시피 목록**이다. 같은 결과물이어도 방법·투입 재료가 다르면 별도 항목이다. 공방 제작과 장비 회수는 각각 별도 체크박스를 켰을 때만 검색 결과에 포함한다. 두 옵션은 `bdo-crafting-browser-options-v1`에 저장하며 기존 제작 계획에는 영향을 주지 않는다. 레시피를 열어도 검색어·필터·더 보기·목표 수량은 초기화하지 않는다.

## 제작 트리와 필요 재료

- PC는 왼쪽 제작 트리 / 오른쪽 필요 재료를 함께 표시한다. 900px 이하에서는 `제작 트리 | 필요 재료` 탭으로 전환하며 전환 시 기존 DOM과 선택값을 유지한다.
- `planTree.ts`는 이미 계산된 `PlanResult.routes`의 DAG를 표현용 트리로 변환한다. 공유 하위 트리는 한 번만 펼치고 이후 경로에서는 원래 설정 위치로 이동하는 참조를 표시한다. 외부 수급 노드는 순환을 다시 펼치지 않는다.
- 트리 카드의 `이 경로 필요`는 부모의 합산 제작 횟수 × 투입량이다. 공유 중간재의 하위 투입량과 제작 횟수는 전체 목표의 합산 기준이며 공유 재고는 경로별로 다시 배분하지 않는다. 중간재 재고로 제작이 불필요하면 해당 투입 가지는 표시하지 않는다.
- 필요 재료는 직접 수급하는 항목과 별도 수급이 필요한 항목만 기본 표시한다. `중간 제작품·목표 재고도 보기`를 켜면 제작할 항목까지 표시하여 해당 재고도 입력할 수 있다. 제작식 편집은 이 표에 섞지 않는다.
- `왜 필요한가?`에서 직접 사용처별 소모량과 목표부터 이어지는 경로를 표시한다. 공유 DAG의 경로 폭증을 막기 위해 목표 경로는 항목당 최대 5개, 탐색은 2,000회로 제한한다. 수량은 기존 계산 결과를 사용하므로 표시 경로 제한이 합계에 영향을 주지 않는다.
- 기존 제작 계획 v1·JSON·계산 수식은 변경하지 않는다. 트리 접기/펼치기는 계산 결과나 사용자 방침을 변경하지 않는다.

`#/crafting/recipe/recipe-<outputId>-<fingerprint>`는 선택 레시피를 새로고침 후에도 유지한다. 기존 `#/crafting/item/<itemId>`는 재료·결과물 사전 링크로 유지한다. 레시피가 없는 호박 같은 원재료는 레시피 검색 결과에 나타나지 않지만 재료 상세 링크로 볼 수 있다.

`pnpm crafting:recipes`는 기존 manifest와 아이템 청크를 읽어 레시피 전용 Zstd 인덱스를 만든다. 13,316개 원본 기록은 그대로 보존하며 내용이 동일한 중복을 합친 10,973개 레시피가 검색된다. 원본 청크를 재생성하지 않아도 실행 가능하다. 전체 청크 생성기에서도 자동 실행된다. `pnpm crafting:verify`는 해시·개수·원본 레시피 연결을 검증한다.

## 대체재

키는 `choices[itemId].substitutions[recipeId][slotId]`다. 다른 요리나 다른 제작식의 같은 재료 칸에 전파하지 않는다. 선택 후 같은 아이템의 수요를 합산한다. 현재는 [공식 요리 가이드](https://www.kr.playblackdesert.com/ko-kr/Wiki?wikiNo=102)의 **일반 등급 채소 5종·곡물 5종**만 1:1로 제공한다. 고급/특상품·고기·생선·모든 요리 예외를 검증 없이 같은 비율로 확장하지 않는다.

유효하지 않은 저장 후보는 임의 아이템으로 계산하지 않고 기본 재료와 진단을 표시한다. 미등록 교환비나 퀘스트 수급량을 제작식으로 꾸며내지 않는다. 실제 교환 레시피가 수집되지 않은 경우 교환 필터는 비어 있을 수 있다.

## 생산량의 범위

자동 규칙은 현재 Codex에서 확인한 채소 절임(`9202`, 숙련9 이상)과 녹아내린 철 조각(`4051`, 장인 이상)의 일반 생산 범위만 연결했다. 출처는 `craftingRules.ts`에 저장한다. 일반 1~4 균등 분포와 최대 프로크 결합은 예측 가정이며 공식 확률 보장이 아니다. 다른 아이템을 전부 1~4로 간주하지 않는다. 미확보 규칙은 기존 수동 값/1개 가정과 경고를 유지한다. 명시적 수동 보정은 자동 규칙보다 우선한다. 회수·부산물에 일반 수율을 자동 적용하지 않는다.

## 저장 호환성과 제한

기존 v1 저장소와 JSON은 유지한다. 구형 배열 번호는 기존 의미로 읽고, 제작 계획에서 해당 선택을 편집하거나 새로 추가하면 안정적인 ID를 저장한다. 이미 ID가 있는 제작식이 사라졌을 때는 다른 배열 번호로 조용히 치환하지 않는다. 선택했던 ID가 없다는 진단과 재선택 UI를 표시한다.

현재 목표 수량은 결과물 아이템별로 합산하고 같은 결과물에는 한 기본 경로를 선택한다. 같은 결과물의 수량을 여러 제작식에 나눠 배분하는 최적화 문제는 아직 지원하지 않는다. DAG가 300개를 넘거나 안전한 수치 범위를 넘는 경우에는 명시적으로 중단한다. 95/99 기준은 기존 조건부 예측이며 실게임 보장이 아니다.

## 회귀 기준

- 순환 중에도 직접 제작 선택이 유지되고 수급↔제작 왕복이 가능할 것.
- 경로 해석은 재고·수량과 독립적일 것.
- 배열/재료 순서가 바뀌어도 같은 제작식 ID를 유지할 것.
- 대체재는 재료 칸별로 저장되며 합계·재고·새로고침에 반영될 것.
- 공통 중간재는 합산 후 올림하고 공유 재고는 한 번만 차감할 것.
- 신규 경로 로딩 동안 기존 트리·설정·재료 목록을 유지할 것.
- 트리의 부모 관계와 합산 목록의 사용처가 일치하고 공유 재료는 한 행으로 합산될 것.
- PC 분할 화면과 모바일 탭 전환에서 선택·재고가 유지되고, 모바일 재료 표만 가로 스크롤할 것.
